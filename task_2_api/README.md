# Тестирование API микросервиса Avito

## Описание проекта
Данный проект содержит полную документацию по тестированию API микросервиса Avito для сервиса объявлений. API представлен в двух версиях: v1 и v2.

## Содержимое проекта
- **TESTCASES.md** — подробное описание тест-кейсов (64 теста)
- **BUGS.md** — отчет о выявленных дефектах (12 дефектов)
- **README.md** — описание проекта и инструкции по тестированию

---

## Тестируемый API

### Базовый URL
https://qa-internship.avito.com

### Доступные версии API

#### API v1 (Основная версия)
| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/api/1/item` | Создание объявления |
| GET | `/api/1/item/{id}` | Получение объявления по ID |
| GET | `/api/1/{sellerId}/item` | Получение всех объявлений продавца |
| GET | `/api/1/statistic/{id}` | Получение статистики (возвращает объект) |

#### API v2 (Расширенная версия)
| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| DELETE | `/api/2/item/{id}` | Удаление объявления по ID |
| GET | `/api/2/statistic/{id}` | Получение статистики (возвращает массив) |

---

## Особенности API

### Версионирование
- v1 - базовая функциональность (создание, чтение)
- v2 - расширенная функциональность (удаление, статистика в другом формате)

### Форматы ответов
- POST /api/1/item — массив с объектом
- GET /api/1/item/{id} — массив с объектом
- GET /api/1/{sellerId}/item — массив объектов
- GET /api/1/statistic/{id} — объект
- DELETE /api/2/item/{id} — объект
- GET /api/2/statistic/{id} — массив объектов

### Параметры объявления
- name — строка, максимальная длина 50 символов
- price — целое число, диапазон 1-999999
- sellerId — целое число, рекомендуется 111111-999999

## Инструкция по тестированию

### Необходимые инструменты
- Postman для ручного тестирования API
- cURL для командной строки
- Любой API клиент (Insomnia, Bruno)

### Подготовка к тестированию
1. Импортируйте Postman коллекцию qa-internship Copy 2, переменная baseUrl уже настроена
2. Подготовьте уникальные sellerId в диапазоне 111111-999999
3. Проверьте доступность API через GET запрос к любому эндпоинту (ожидается 404, что означает работа сервиса)

### Чек-лист перед тестированием
- Проверена доступность API
- Импортирована Postman коллекция
- Подготовлены уникальные sellerId (111111-999999)
- Изучены различия между v1 и v2 API
- Ознакомлены с известными багами из файла BUGS.md
- Подготовлен шаблон для записи результатов

## Рекомендации по тестированию

### Общие рекомендации
- Каждый тест должен создавать свои данные для изоляции
- Используйте уникальные sellerId для каждого запуска
- Проверяйте взаимодействие v1 и v2 при кросс-версионном тестировании
- Фиксируйте все обнаруженные проблемы

### Особенности версий
- v1: тестируйте создание, получение, статистику в формате объекта
- v2: тестируйте удаление, статистику в формате массива
- Кросс-версия: создание через v1, удаление через v2, проверка через v1

### Приоритеты тестирования
- Высокий приоритет: создание объявления, получение по ID, удаление, базовые негативные сценарии
- Средний приоритет: список продавца, статистика, удаление несуществующего
- Низкий приоритет: нагрузочное тестирование, корнер-кейсы
