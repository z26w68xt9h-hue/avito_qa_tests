# Тест-кейсы для API микросервиса Avito

## Базовый URL
`https://qa-internship.avito.com`

## Доступные версии API
- **API v1** - основная версия (POST, GET)
- **API v2** - расширенная версия (добавлен DELETE)

---

## Эндпоинты (из Postman-коллекции)

### API v1
| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/api/1/item` | Создать объявление |
| GET | `/api/1/item/{id}` | Получить объявление по ID |
| GET | `/api/1/{sellerId}/item` | Получить все объявления продавца |
| GET | `/api/1/statistic/{id}` | Получить статистику |

### API v2
| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| DELETE | `/api/2/item/{id}` | Удалить объявление по ID |
| GET | `/api/2/statistic/{id}` | Получить статистику (v2) |

## 11. Различия между API v1 и v2

| Характеристика | API v1 | API v2 |
|----------------|--------|--------|
| **Создание** | POST `/api/1/item` | Отсутствует |
| **Получение** | GET `/api/1/item/{id}` | Отсутствует |
| **Список продавца** | GET `/api/1/{sellerId}/item` | Отсутствует |
| **Статистика** | GET `/api/1/statistic/{id}` → объект | GET `/api/2/statistic/{id}` → массив |
| **Удаление** | Отсутствует | DELETE `/api/2/item/{id}` |

## Использованные техники тест-дизайна

| Техника | Применение | Примеры |
|---------|------------|---------|
| **Классы эквивалентности** | Разделение входных данных на валидные/невалидные | sellerId: валидный (111111-999999), невалидный (<111111, >999999, строка) |
| **Граничные значения** | Проверка границ диапазонов | price: 0, 1, 999999, 1000000; sellerId: 111111, 999999 |
| **Попарное тестирование** | Комбинации параметров | Разные комбинации name, price, sellerId |
| **Предугадывание ошибок** | Типичные ошибки пользователей | Пустые поля, спецсимволы, XSS, SQL инъекции |
| **Идемпотентность** | Повторные запросы | Два одинаковых POST → разные ID, DELETE дважды → 200/404 |
| **Кросс-функциональное** | Взаимодействие разных версий API | Создание v1, удаление v2, статистика v1/v2 |

## Примечания по тестированию

### Важные особенности API
1. **Версионирование**: API v1 и v2 имеют разные форматы ответов
2. **Статистика**: 
   - v1 возвращает объект: `{"likes": 0, "viewCount": 0, "contacts": 0}`
   - v2 возвращает массив: `[{"likes": 0, "viewCount": 0, "contacts": 0}]`
3. **Удаление**: Доступно только в v2 через DELETE метод
4. **sellerId**: Рекомендуется использовать значения 111111-999999
5. **price**: Принимает значения от 1 до 999999

### Рекомендации
1. Используйте уникальные sellerId для каждого тестового запуска
2. Проверяйте обе версии API при тестировании статистики
3. Тестируйте кросс-версионные сценарии (создание v1, удаление v2)
4. Документируйте все различия между версиями
